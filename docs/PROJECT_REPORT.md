# بحث وتقرير مشروع تواصل (Tawasol)

> واجهة اجتماعية ثنائية اللغة (العربية RTL / الإنجليزية LTR) — مشروع مقدم إلى الدكتور في المعهد، من تنفيذ فريق من خمسة طلاب.
>
> الرابط المنشور: https://mohamedharon318-ship-it.github.io/tawasol/
> المستودع: https://github.com/mohamedharon318-ship-it/tawasol
> تاريخ التقرير: 24 نوفمبر 2026

## 1. الملخص التنفيذي

"تواصل" تطبيق ويب اجتماعي تجريبي يسمح للمستخدم بإنشاء منشورات، التفاعل مع المنشورات (Like / Love / Care)، متابعة القصص، الدردشة، تعديل الملف الشخصي، وضبط اللغة والمظهر والإشعارات. صُمّم ليعمل **بدون خادم خاص**: الواجهة مكتوبة بالكامل في المستودع، والبيانات التجريبية تُحفظ في متصفح كل زائر، بينما تستدعي الواجهة واجهة برمجية خارجية جاهزة لأ部分 عمليات الدخول والمنشورات.

الهدف من المشروع ليس فقط بناء واجهة جميلة، بل ممارسة العمل الهندسي المتكامل: تحليل المتطلبات، تصميم المعمارية، تقسيم العمل، الاختبار، ضمان الجودة، والنشر المستمر على GitHub Pages.

النتيجة النهائية: موقع منشور ويعمل، 27 اختبارًا تلقائيًا ناجحًا، فحص lint و build نظيف، وتقييم Lighthouse **1 / 1 / 1** (الوصولية، أفضل الممارسات، SEO) على الصفحات الرئيسية.

## 2. مشكلة المشروع والهدف منه

| البند | التفصيل |
|---|---|
| المشكلة | الحاجة إلى منصة تواصل عربية بسيطة وسريعة، تعمل مباشرة في المتصفح من غير تجهيز خادم، وتدعم الاستخدام بالعربية والإنجليزية. |
| الهدف | بناء واجهة تفاعلية كاملة المزايا التجريبية، قابلة للعرض والمناقشة، وقابلة لتطويرها لاحقًا بربط خادم حقيقي. |
| النطاق | واجهة فقط (Front-end): لا يوجد كود خادم داخل المستودع. أي بيانات مشتركة بين المستخدمين تتطلب مرحلة لاحقة. |
| القيد الأساسي | البيانات محلية (`localStorage`)، لذا كل زائر يرى بياناته هو فقط؛ وهذا موثّق صراحةً داخل الواجهة وملف README. |

## 3. التقنيات المستخدمة

| الطبقة | التقنية | سبب الاختيار |
|---|---|---|
| الواجهة | React 19 + TypeScript | مكوّنات قابلة لإعادة الاستخدام، أنواع آمنة وقت التجميع. |
| البناء | Vite 6 | بدء سريع، بناء مُحسَّن، دعم `base: '/tawasol/'` للنشر تحت مسار فرعي. |
| التنسيق | Tailwind CSS 3 | نظام تصميم موحّد عبر متغيرات CSS (`primary`، `ink`، `muted`) ودعم RTL. |
| التوجيه | React Router 7 مع `HashRouter` | يتجنّب خطأ 404 عند تحديث الصفحة على GitHub Pages. |
| الأيقونات والخطوط | Lucide React + Fontsource (Tajawal / Inter) | أيقونات متسقة وخطوط محمّلة محليًا بلا اعتماد على خدمة خارجية. |
| الحالة | React Context (Auth / Language / Theme / Toast) | حالة عامة بسيطة بدون مكتبات إضافية. |
| الاختبار | Vitest + jsdom (27 اختبارًا) | اختبار طبقة الخدمات والمنطق المحلي. |
| الجودة | ESLint + TypeScript `--noEmit` | كشف الأخطاء قبل النشر. |
| النشر | GitHub Actions + GitHub Pages | بناء ونشر تلقائي عند كل push على `main`. |
| التحسين | Service Worker مكتوب يدويًا | تخزين الملفات الثابتة فقط، مع تنقّل `network-first`. |

## 4. المعمارية العامة

```text
المتصفح (الزائر)
├── pages/          صفحات التطبيق (lazy-loaded)
├── components/     مكوّنات مشتركة (UI / posts / stories / layout / ai)
├── context/        الحالة العامة: دخول، لغة، ثيم، تنبيهات
├── hooks/          useDataVersion وغيرها
├── services/       طبقة البيانات: db.ts + *.service.ts + ai.ts
├── lib/            api.ts + storage.ts + image.ts + lang.ts
└── localStorage    مفاتيح tawasol:* (قاعدة البيانات التجريبية)
          │
          └── API خارجي (route-posts.routemisr.com)
                    ├── POST /users/signin
                    ├── POST /users/signup
                    ├── GET  /posts/feed
                    └── POST /posts
```

**فكرة التصميم:** المكوّنات لا تتعامل مع `localStorage` مباشرة، بل تستدعي الخدمات في `src/services/`. لذلك عند ربط خادم حقيقي مستقبلاً تُستبدل الخدمات فقط دون إعادة كتابة الواجهة.

## 6. إدارة البيانات ("قاعدة البيانات" في المشروع)

- لا توجد قاعدة بيانات SQL داخل المشروع؛ البيانات التجريبية تُحفظ في **`localStorage`** بمفاتيح تبدأ بـ `tawasol:*` عبر `src/services/db.ts` و`src/lib/storage.ts`.
- عند أي تعديل يُطلق حدث **`tawasol:changed`**، وتستجيب الواجهة عبر `useDataVersion` لتحديث العرض تلقائيًا.
- **إصلاح ذاتي:** إذا كانت البيانات قديمة أو تالفة أو عُرضت أسماء تجريبية قديمة، تقوم `repairDemoData()` و `loginLocal()` بترميم الحسابات عند الحاجة.
- **إعادة الضبط:** زر في الإعدادات يعيد البيانات الأصلية بعد نافذة تأكيد.
- **الصور:** تُضغط إلى JPEG داخل المتصفح (الهدف ~320 كيلوبايت) قبل الحفظ، مع فحص حد السعة (~4.5 ميجابايت) وتخزينها كـ `data URL`.
- **الحدود:** البيانات خاصة بكل متصفح، لا تتزامن بين الأجهزة، وتُمسح لو مسح المستخدم بيانات الموقع. هذا معلن للمستخدم في صفحتي الدخول والإعدادات.

## 7. المصادقة والأمان

1. **مساران للدخول:**
   - حسابات تجريبية محلية بالكامل: تُضغط ببطاقتها في صفحة الدخول، وتعمل حتى لو كان الـ API غير متاح. كلمة المرور التجريبية معرّفة مرة واحدة في `src/data/demo.ts` عبر الثابت `DEMO_PASSWORD` وهي للعرض فقط، وليست سرًا حقيقيًا.
   - دخول حقيقي عبر `POST /users/signin` وإنشاء حساب عبر `POST /users/signup`.
2. **الجلسة:** تُحفظ في `localStorage`. في منتج حقيقي يُفضّل نقلها إلى cookie مع `httpOnly` من الخادم.
3. **سياسة الأمان:** `Content-Security-Policy` في `index.html` يقيّد المصادر، مع ملاحظة أن `'unsafe-inline'` مطلوب أثناء التطوير ويُنصح باستبداله بـ header مع nonce في الإنتاج.
4. **مساعد AI:** يدعم استدعاء نموذج متوافق مع OpenAI عبر `VITE_AI_API_URL`. من دون مفتاح أو وسيط، يعرض المساعد حالة "غير مُعدّ" بدل ادّعاء وجود رد حقيقي. في الإنتاج يجب أن يبقى المفتاح على خادم وسيط لا في الواجهة أو المستودع.

## 8. النشر والجودة

- **خط الأنابيب:** push على `main` ⇒ `npm ci` ⇒ `npm run build` ⇒ رفع `dist` ⇒ `actions/deploy-pages` ⇒ الرابط العام.
- **المصدر على GitHub:** `GitHub Actions` (ليس فرع `gh-pages`)، وآخر تشغيل ناجح هو رقم **#19** لل commit `c6bb224`.
- **المسار:** `vite.config.ts` يضبط `base: '/tawasol/'`، و`HashRouter` يمنع 404 عند تحديث المسارات.
- **Service Worker:** يُسجّل في الإنتاج فقط بـ `updateViaCache: 'none'`. طلبات التنقل تذهب للشبكة أولًا، والملفات الثابتة تُخزّن عند الطلب؛ واجهة الـ API لا تُعترض. المراجع الحالية: `tawasol-static-v4`.
- **الاختبارات:** `npm test` → 6 ملفات، **27 اختبارًا ناجحًا**؛ `npm run lint` نظيف؛ `npm run build` ناجح.
- **قياسات المتصفح:** Lighthouse سجّل **1 للوصولية، 1 لأفضل الممارسات، 1 لـ SEO** في صفحات الدخول والرئيسية والإعدادات، دون فشل مُسجّل. أُصلحت خلال العمل مشكلات تباين الألوان، وتعارض `aria-label` في البحث، وحجم زر إظهار كلمة المرور.
- **التوثيق البصري:** لقطات من الموقع الحي في `docs/screenshots/` ومضمّنة في README.

## 10. القيود والعمل المستقبلي

1. إنشاء خادم بسيط (Node/Express أو ما شابه) وقاعدة بيانات، ونقل الخدمات المحلية إليه تدريجيًا.
2. استبدال الجلسات بـ `httpOnly cookies`، وتنفيذ إعادة تعيين كلمة مرور فعلية.
3. وضع مفتاح مزود AI خلف خادم وسيط.
4. رفع الصور إلى تخزين حقيقي بدل `data URL`، وإضافة pagination للمنشورات.
5. إضافة اختبارات E2E (مثلاً Playwright) للحسابات التجريبية والمسارات المحمية.
6. اختياري: ربط دومين مخصص (الخطوات موثّقة في README) أو دعم offline كامل.

## 12. الخلاصة

أثبت المشروع إمكانية بناء تطبيق اجتماعي تفاعلي بالكامل في المتصفح، بواجهة عربية سليمة وتجربة مستخدم متكاملة، من غير خادم، مع الحفاظ على قابلية التوسّع: طبقة الخدمات معزولة بحيث يمكن استبدال مصدر البيانات لاحقًا دون إعادة بناء الواجهة. التقرير يوصي بالبقاء على النسخة الحالية كعرض تجريبي مكتمل، ثم الانتقال إلى مرحلة الباك إند إذا أُريد استخدامه كمنتج متعدد المستخدمين.
